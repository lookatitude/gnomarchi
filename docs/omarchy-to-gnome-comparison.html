Omarchy → Gnomarchi

Deep comparison of Omarchy Linux (Hyprland + Quickshell) with a GNOME-based Arch port, and how to replicate each feature.

In review Updated 2026-10-20 Omarchy 4.x Quattro gnomarchi greenfield

Verdict

Gnomarchi can keep ~60–70% of Omarchy’s product value by swapping the compositor stack and re-homing the opinionated layer on GNOME Shell + a small CLI. The hard part is not packages: it is Omarchy’s unified Quickshell (bar, launcher, menu, notifications, lock, panels) and Hyprland’s tiling semantics. Those need deliberate GNOME replacements, not a config rename.

i

What “this system” is today. /home/miguelp/Projects/gnomarchi is an empty repo. Comparison is Omarchy 4 (as shipped) versus a greenfield GNOME Arch product with the same omakase goals: fast install, keyboard-first UX, whole-desktop themes, agent-native tooling.

Port as-is

Arch base, mise, Neovim/LazyVim, Docker, Chromium, Nautilus, themes-as-data, omarchy-style CLI wrappers, agent launchers, Snapper/Btrfs, gaming/NVIDIA install paths.

Must redesign

Hyprland tiling, Quickshell shell, Lua bindings, scratchpads, window rules, Hyprland portals, SDDM+hypr session, Omarchy menu JSONC in Quickshell.

GNOME gift

Settings app, Quick Settings, Night Light, GDM lock, notifications, portals, accessibility, multi-monitor Settings, Flatpak, libadwaita apps already on Omarchy’s list (Nautilus, Evince).

Baseline: what Omarchy actually is

Omarchy is opinionated Arch with a custom desktop product on top, not “Hyprland + dots.” Quattro (4.x) moved the entire shell into Quickshell: bar, launcher, nested Omarchy menu, notifications, OSDs, control panels, lock screen, and polkit — one process, plugin system, theme-aware. Hyprland remains the compositor with Lua config (hyprland.lua, bindings.lua, …).

Window management: Hyprland → GNOME

This is the largest UX delta. Omarchy’s identity is tiling + Super-chord navigation. GNOME is overview + floating (+ optional tiling extension).

O1 — PaperWM (recommended default metaphor)

Scrollable horizontal tiling, per-workspace strip, scratch windows, strong Super-key navigation. Closer to Omarchy’s “scrolling layout” than to dwindle trees. Actively maintained for modern GNOME.

  • Map Super+Left/Right focus to PaperWM’s window strip.
  • Map workspaces to GNOME workspaces; accept different multi-monitor semantics.
  • Use PaperWM scratch for Omarchy Super+S scratchpad.
  • Accept: no dwindle binary tree; no Hyprland window groups identical to Omarchy.

O2 — Forge (i3/Sway-like)

Tree splits, vim keys, stacked/tabbed layouts. Closer to dwindle for power users. Maintenance risk (upstream has sought a new maintainer); fork or pin carefully.

O3 — Stock GNOME + light tiling

Overview, Super+number workspaces, edge tiling / Tiling Assistant. Lowest maintenance, furthest from Omarchy feel. Good for a “GNOME comfort” edition, weak as an Omarchy spiritual successor.

!

D1: Pick one tiling metaphor early and design the default hotkey table around it. Trying to emulate every Hyprland bind on GNOME produces conflicts with Shell’s reserved Super shortcuts.

F1 — Menu is the product spine

Omarchy’s Install / Remove / Setup / Style / Trigger / Learn tree is how non-experts operate the system. Port the data (JSONC menu definitions + shell scripts) before the UI toolkit. UI options:

  • GTK4 + libadwaita command palette (recommended): themable, agent-editable, no Shell API churn every GNOME release.
  • GNOME Shell extension: deeper integration, higher maintenance across Shell versions.

Theming system

Omarchy themes are multi-surface packs (shell, Hyprland, foot, nvim, btop, Chromium, unlock/Plymouth art). Gnomarchi should keep the same pack layout with different renderers:

theme/
  colors.toml          # semantic 24-color set (keep)
  gtk.css              # or Adwaita color overrides
  gnome-shell.css      # User Themes extension
  foot.ini | ghostty
  neovim.lua / lazy
  btop.theme
  chromium-theme/
  wallpaper/
  plymouth/            # optional

gnomarchi theme set "Tokyo Night" should:

  1. Symlink/copy pack into ~/.local/state/gnomarchi/current/theme
  2. Apply GTK via gsettings / xdg-desktop-portal color-scheme
  3. Reload Shell theme (User Themes)
  4. Rewrite terminal + nvim + btop from colors.toml (reuse Omarchy generators where possible)
  5. Set wallpaper; notify Chromium if theme extension present
✓

F2: The 24-color semantic expansion and nvim/VS Code/btop autogen from Quattro are DE-agnostic. Steal that pipeline; only rewrite shell/Hyprland emitters into GTK/Shell emitters.

Hotkeys and discoverability

Omarchy’s Super+K keybinding cheatsheet is a teaching surface. Replicate with:

  • A gnomarchi-keybindings viewer (read from a YAML/JSON source of truth, not only dconf dumps).
  • First-login notification → open cheatsheet (same Quattro idea).
  • Store binds in one file that both GNOME custom shortcuts and docs generate from (avoid drift).

GNOME Settings → Keyboard → Custom Shortcuts can hold app launches. Tiling binds live in the extension. Conflict resolution against Shell defaults is mandatory QA.

Agents and AI (mostly portable)

This layer is Omarchy’s differentiator and the least tied to Hyprland:

  • mise lazy installs for claude/codex/opencode/…
  • Default agent picker + a / Super+Shift+Ctrl+A
  • Multi-account switching and usage aggregation
  • Crash notification → diagnose skill
  • Agent skill for “change my OS”

Change for GNOME: rewrite the OS skill to edit dconf, GSettings, extension prefs, and GTK theme packs — never Hyprland Lua or Quickshell QML. Bar usage meters need a Shell extension or a standalone GTK “Agents” window launched from the menu.

Developer tooling (keep)

Install → languages via mise, Docker, Lazygit, Herdr/tmux layouts, Neovim defaults, optional VS Code/Cursor/Zed — all should ship unchanged. Terminal default remains Foot or Ghostty; set GNOME’s default terminal accordingly. Nautilus stays; optional terminal-cwd open via Nautilus extension (Omarchy already uses nautilus-python patterns).

Keep / adapt / drop

Keep as-is

Arch, pacman product packages, mise, agents CLIs, nvim stack, docker, chromium+webapps, theme color schema, menu script actions, Snapper/factory reset, gaming installers, LocalSend, ufw, fonts, compose emojis.

Adapt

Theme appliers, capture scripts, keybinding source of truth, agent OS skill, first-boot UX, bar indicators, notification keybinds, default Super chord table.

Drop or rewrite

Hyprland, Quickshell, hyprlock/hypridle era remnants, Walker/Waybar/Mako (already gone upstream), hyprland portal, SDDM session, Lua bind DSL, Omarchy shell plugin API.

Recommended Gnomarchi shape

  1. Session: GNOME Wayland on GDM, curated gnome package set (not full kitchen sink).
  2. Tiling: PaperWM enabled by default; document Forge as alternate profile.
  3. Extensions (pinned versions): PaperWM, User Themes, Just Perfection, Clipboard Indicator (or ClipMaster), Caffeine, optional Blur my Shell, optional Dash to Dock.
  4. Product CLI: gnomarchi with menu, theme, update, agent, default — same verbs as Omarchy.
  5. Menu UI: GTK4 command palette driven by shared JSONC (port Omarchy menu definitions).
  6. Themes: Port popular Omarchy packs with GTK/Shell emitters.
  7. Defaults: Foot + Neovim + Chromium + Nautilus; Super-centric app hotkeys.
×

R1 — Do not run Quickshell beside GNOME Shell as a “hybrid.” Two shells fighting portals, lock, and layers will feel worse than either alone. Commit to GNOME Shell as the only shell.

Build phases

  • Phase 0 — Repo skeleton: package lists, GNOME session target, gnomarchi CLI stub, theme schema copy
  • Phase 1 — Bootable Arch+GNOME image with pinned extensions and PaperWM defaults
  • Phase 2 — Port menu JSON + install/remove scripts; GTK menu UI
  • Phase 3 — Theme engine (GTK/Shell/terminal/nvim) + 5 showcase themes
  • Phase 4 — Hotkey table + Super+K cheatsheet + first-login coach
  • Phase 5 — Agents stack + crash watcher + rewritten OS skill
  • Phase 6 — Capture/OCR/QR wrappers, hardware helpers, ISO polish, factory reset

Q1: Should Gnomarchi’s default feel be “Omarchy keybinds on PaperWM” or “stock GNOME slightly omakase’d”? That single choice drives the hotkey table and marketing honesty.
