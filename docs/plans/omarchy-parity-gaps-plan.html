Omarchy parity gaps & implementation plan

What is missing vs Omarchy’s top bar, widgets, and AI agent stack — and how to close it on GNOME without cloning Quickshell wholesale.

● Review 2026-10-20 Omarchy Quattro bar + AI manual gnomarchi tree as of post-T7 stubs

Verdict

F1: Screenshots look like stock GNOME because that is almost all that is implemented. Theme emitters (wallpaper / GTK CSS / Ghostty colors) and a non-interactive Agents catalog window exist; the Omarchy product surface — configurable bar widgets, mise-lazy agent CLIs, usage meters, default-agent launch, Make-something wiring — does not.

F2: Closing the gap users care about is mostly not a custom top-bar rewrite. It is (1) a real agent runtime (mise stubs + CLI + usage + skills), (2) panel presence via StatusNotifier + one thin Shell extension for chrome that must live in the bar, (3) first-party widget plugins that map Omarchy’s catalogue onto those runtimes.

D1 tension: ADR “stock GNOME, no custom bar” deferred bar-drag and Quickshell clones. That decision correctly blocks a full bar engine, but it currently also blocks the visible Omarchy feel. Recommend a soft revision (D1′): keep GNOME Shell chrome as the bar host; ship indicators + optional extension widgets; still refuse a Quickshell/Hyprland replacement.

D1 decision fork

O1 — Keep strict D1

Stock panel forever. Agents only as GTK window + menu. Indicators optional and easy to miss. Matches ADR; fails the user’s “looks like Omarchy” bar expectation.

O2 — D1′ recommended

GNOME Shell remains the bar. First-party AppIndicator/StatusNotifier pack + one version-pinned Shell extension for agents usage chip / workspace-like chrome that indicators cannot do. Still no bar-drag, no Quickshell host.

O3 — Custom bar engine

Replace GNOME top bar (Dash-to-Panel fork, Layer-shell panel, etc.). Closest visual clone; fights Shell updates and D1 hard. Defer to P9 unless D1 is fully overturned.

→

Recommended: adopt O2 / D1′ for the next build wave. Update ADR + registry: move “bar widgets” from vague adapt to concrete first-party plugins; keep “bar-drag / full bar” deferred.

Implementation plan

i

Order is dependency-driven: agents without panel still deliver product value; a panel without agents is empty chrome. Do Phase A before polishing screenshots.

A — Agent core (highest leverage)

  • Ship mise + lazy tool definitions for Omarchy’s agent command set (start with claude, codex, opencode, grok; add the rest from the AI manual table).
  • Extend overlay: install mise, seed ~/.config/mise/config.toml (or gnomarchi-owned tool stubs under ~/.local/bin), print first-run default-agent invite that actually launches setup.
  • CLI: gnomarchi default agent, agent prompt, agent launch, agent usage-update (JSON cache), later agent account *.
  • Ghostty/shell seed: aliases a/cy/cx/c; GSettings custom keybinding for default agent in Ghostty.
  • Skill installer: symlink gnomarchi-* skills into Claude/Codex/Pi/Gemini/Hermes/~/.agents/skills.
  • Agents window: clickable rows; Make something calls agent prompt --skill …; show usage from cache; empty-state sign-in for Claude/Codex/Grok.
  • Theme emitters for agent skins + nvim (minimum for visible parity).

Exit: fresh overlay VM can pick Claude or Codex, see usage after login, launch Make-something Theme, and change Ghostty+nvim+agent colors via theme set.

B — Panel presence (make it show up in screenshots)

  • Implement real status-indicator adapter (Ayatana/AppIndicator or StatusNotifierItem via PyGObject).
  • Overlay enables a tray host extension (e.g. Ubuntu AppIndicators / similar Arch package) so indicators appear on GNOME 45+.
  • First-party gnomarchi.agents indicator: left-click Agents window, right-click launch default agent.
  • Optional thin Shell extension (explicit opt-in, version-pinned) for an in-bar usage chip matching Omarchy’s bar icon density.
  • Wire gnomarchi-bus: Agents.Open, Theme.Changed, Menu.Open.

Exit: desktop screenshot shows an agents (and optionally weather) control in/near the top bar, not only a floating GTK window.

C — First-party widget pack

  • gnomarchi.weather — indicator + overlay forecast.
  • gnomarchi.system-update — checkupdates timer + indicator.
  • gnomarchi.tailscale — if tailscale present.
  • gnomarchi.media — only if Quick Settings is judged insufficient.
  • Templates + gnomarchi-plugin skill updates for status-indicator scaffolds; plugin clone for first-party.
  • Crash-capture user-service + gnomarchi-diagnose-crash skill.

D — Configurability (Omarchy shell.json analogue)

  • ~/.config/gnomarchi/shell.toml: enabled indicators, order, agents panel prefs (refresh interval, autoswitch later).
  • Menu JSONC tree: Install › AI / Dev / …, Setup › Defaults › Agent, Style, Trigger — modules appendable by agents.
  • gnomarchi plugin scaffold --runtime status-indicator (and gated Shell extension scaffold).
  • Document widget → runtime map in README; refresh screenshots after A+B.

E — Explicitly later / still deferred

  • Full bar replacement, edge drag, vertical bar (O3).
  • Multi-account autoswitch / cross-machine account copy (port after single-account usage works).
  • Desktop AI apps menu (ChatGPT/Claude desktop/Hermes Desktop/…).
  • Marketplace; PaperWM profile; video wallpaper.

Risks

R1 — AppIndicator support on vanilla GNOME Wayland is extension-dependent; overlay must install and enable a known-good host or indicators are invisible again.

R2 — Shell extension API churn; keep agents chip tiny and version-gated; prefer StatusNotifier for everything else.

R3 — Vendor lock / ToS for agent CLIs: ship launchers only, never redistribute proprietary binaries; mise lazy install matches Omarchy.

R4 — Scope creep into O3 custom bar will delay agents; hold the line on D1′.

A1 — Next build wave: Phase A then B; recapture screenshots; then open Phase C widgets as first-party plugins.
