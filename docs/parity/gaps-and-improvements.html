Gaps & improvements

Post–v0.0.1-beta.1 assessment. Manual feature map is 43/43 “done” on the GNOME adaptation path; product maturity is not.

● Review ● A1–A3 remediated in-tree (beta) 2026-10-20 v0.0.1-beta.1

Verdict

!

“Done” means adapted, not Omarchy-identical. Hyprland/Quickshell are deliberately replaced (D1′). The largest remaining gaps are distribution trust, ISO proof, UX fidelity on tiling/shell, and repo weight — not missing menu chapters.

Findings

F1 High No production install channel with signatures AUR sha256sums=('SKIP'); pacman example still Optional TrustAll / example.invalid; security doc F4 residual open

F9 Low Registry overstates readiness features/registry.yaml marks ISO/update/session rows done; operators reading only the registry will misread beta maturity

Suggested improvements

Distribution

  • Publish a signed .pkg.tar.zst (or real AUR package with pinned checksums) and drop TrustAll before any public mirror.
  • Attach a tested ISO (or document “overlay-only until v0.1”) so README channels match artifacts.
  • Split theme media: ship palette + wallpaper webp in core; lazy-fetch intro videos / full backgrounds.

Product feel

  • First-run: offer PaperWM (or clear tiling profile) instead of burying it under Install.
  • Tighten hotkey cheatsheet vs Omarchy Super+* map; flag intentional GNOME divergences in-app.
  • Replace or deepen wrapper apps where the substitute fails the daily loop (esp. Monologue / Signed).

Hardening & quality

  • CI: unittest on PR + one scheduled “overlay dry-run” on Arch container; later a GNOME VM smoke.
  • Move parity-v2 / omarchy-manual PNGs to release assets or LFS; keep README JPEGs in-tree.
  • Add a status enum beyond feature-map done: adapted | shipped | proven.
